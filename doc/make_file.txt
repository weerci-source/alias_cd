Этот файл CMakeLists.txt предназначен для сборки плагина alias_cd для файлового менеджера FAR Manager (точнее, его кросс-платформенной версии far2l). Он описывает конфигурацию проекта на языке CMake, включая настройку компиляции, линковку, определение макросов, а также опциональную сборку модульных тестов с использованием Google Test.

Ниже приведён подробный разбор всех секций файла.
1. Заголовок и минимальная версия CMake
cmake

cmake_minimum_required(VERSION 3.31)
project(alias_cd)

    Устанавливается минимальная требуемая версия CMake 3.31 (это очень свежая версия, что означает использование современных возможностей).

    Объявляется имя проекта – alias_cd.

2. Настройка стандарта C++
cmake

set(CMAKE_CXX_STANDARD 23)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

    Код компилируется в режиме C++23.

    Требование стандарта обязательно (ON), если компилятор не поддерживает C++23 – сборка прервётся.

    Отключаются расширения компилятора (OFF), чтобы гарантировать строгое соответствие стандарту.

3. Определение исходных файлов основного модуля
cmake

set(SOURCES alias_cd.cpp)

    В переменную SOURCES помещается единственный файл alias_cd.cpp – точка входа плагина.

4. Создание динамической библиотеки (модуля FAR)
cmake

add_library(alias_cd MODULE ${SOURCES})

    Создаётся цель alias_cd типа MODULE – это динамически загружаемая библиотека (плагин). В отличие от SHARED, модули не линкуются во время сборки, а загружаются во время выполнения.

5. Линковка с внутренней статической библиотекой
cmake

target_link_libraries(alias_cd PRIVATE logger_lib)

    Модуль alias_cd линкуется с библиотекой logger_lib (которая объявлена ниже) с областью видимости PRIVATE – это значит, что зависимости не распространяются на другие цели, использующие alias_cd.

6. Определения препроцессора (макросы)
cmake

target_compile_definitions(alias_cd
    PRIVATE
        -DWINPORT_DIRECT
        -DUNICODE
        -DFAR_DONT_USE_INTERNALS
)

    Для компиляции alias_cd добавляются три макроса:

        WINPORT_DIRECT – вероятно, указывает на использование прямого доступа к функциям Windows-порта far2l.

        UNICODE – включает поддержку широких символов (UTF-16), что необходимо для FAR API.

        FAR_DONT_USE_INTERNALS – отключает использование внутренних (нестабильных) частей SDK FAR, обеспечивая совместимость с публичным API.

7. Добавление путей для поиска заголовочных файлов
cmake

target_include_directories(alias_cd
    PRIVATE /home/dima/far2l-dev/src/far2l/far2sdk/
)

    Указывается директория с FAR SDK (путь к заголовкам far2sdk). Область видимости PRIVATE – эти пути нужны только для компиляции самого модуля, не экспортируются наружу.

8. Отладочный вывод (пути включения)
cmake

get_target_property(INC_DIRS alias_cd INCLUDE_DIRECTORIES)
message(STATUS "alias_cd include dirs: ${INC_DIRS}")

    Получается свойство INCLUDE_DIRECTORIES цели alias_cd и выводится в консоль CMake (статусное сообщение). Это помогает проверить, какие директории действительно используются.

9. Настройка свойств выходного файла плагина
cmake

set_target_properties(alias_cd
    PROPERTIES
        PREFIX ""
        SUFFIX ".far-plug-wide"
)

    PREFIX "" – убирает стандартный префикс (lib в Unix, cyg в Cygwin и т.д.), чтобы имя файла начиналось непосредственно с alias_cd.

    SUFFIX ".far-plug-wide" – вместо стандартного расширения .so / .dll / .dylib используется суффикс .far-plug-wide (это соглашение для плагинов FAR2L, которое позволяет загрузчику распознавать их).

10. Статическая библиотека logger_lib
cmake

add_library(logger_lib STATIC
    models/alias.cpp
)

    Создаётся статическая библиотека из одного исходного файла models/alias.cpp.
    (Несмотря на название logger_lib, она содержит только код из alias.cpp – возможно, это часть логики плагина или утилитарный код.)

cmake

set_target_properties(logger_lib PROPERTIES POSITION_INDEPENDENT_CODE ON)

    Включается генерация позиционно-независимого кода (PIC) – обязательное требование при линковке статической библиотеки в динамический модуль (иначе на некоторых платформах возникнут ошибки).

cmake

target_include_directories(logger_lib
    PUBLIC ${CMAKE_CURRENT_SOURCE_DIR}
)

    Для logger_lib добавляется текущий каталог проекта (${CMAKE_CURRENT_SOURCE_DIR}) как путь для поиска заголовков с областью видимости PUBLIC. Это позволяет потребителям logger_lib (в частности, alias_cd) видеть заголовки, находящиеся в корне проекта (например, models/alias.h), не добавляя их отдельно.

11. Опциональная сборка тестов с Google Test
cmake

option(BUILD_TESTS "Build unit tests" ON)

    Объявляется опция BUILD_TESTS (по умолчанию включена), позволяющая включать или отключать сборку тестов.

cmake

if(BUILD_TESTS)
    enable_testing()
    include(FetchContent)
    FetchContent_Declare(
        googletest
        GIT_REPOSITORY https://github.com/google/googletest.git
        GIT_TAG release-1.12.1
    )
    FetchContent_MakeAvailable(googletest)
    add_subdirectory(tests)
endif()

    Если опция активна:

        Включается поддержка тестирования CMake (enable_testing()).

        Подключается модуль FetchContent, который загружает внешние зависимости.

        Объявляется зависимость googletest (версия release-1.12.1) из официального репозитория GitHub.

        Выполняется загрузка, конфигурация и сборка Google Test (FetchContent_MakeAvailable).

        Добавляется поддиректория tests, в которой, как предполагается, находятся CMakeLists.txt и исходники тестов, использующие Google Test.

Общая структура и назначение

    Проект собирает плагин FAR2L, который расширяет функциональность командной строки (вероятно, связан с командой cd и управлением алиасами).

    Основной код плагина находится в alias_cd.cpp, вспомогательная логика вынесена в models/alias.cpp и собрана в статическую библиотеку для удобства.

    Поддерживается кросс-платформенная сборка благодаря использованию far2sdk и макросов.

    Тесты интегрированы через современный механизм FetchContent, что упрощает воспроизводимость и не требует ручной установки Google Test.

Возможные замечания

    Путь к SDK (/home/dima/far2l-dev/...) жёстко задан – для переносимости лучше использовать переменную или найти SDK через find_package или find_path.

    Название logger_lib не отражает содержимое (там только alias.cpp), но это не влияет на функциональность.

    Используется очень новая версия CMake (3.31), что может потребовать обновления на целевых системах.
